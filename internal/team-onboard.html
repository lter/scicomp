SciComp Team Onboarding

Caution Relevant to SciComp Only!

This document is primarily meant for members of the LTER Scientific Computing team.

So, you’re a new member of the LTER Scientific Computing (SciComp) team: welcome! We are excited to have you join us and we hope that the onboarding instructions below are clear and easy-to-follow.

The goal of this page is to detail which tools we use (and why we use them) but we’ll also provide some larger context for LTER’s/NCEAS’ approach.

What You Need to Do…

As Soon As Possible

  • Get on GitHub
  • Get an NCEAS’ Server Account
  • Join Slack
  • Read Background Literature

We rely heavily on GitHub, and there are a few things you must do to get set up. See below for details:

  1. Create a personal GitHub account
  2. Personalize your GitHub profile
    • E.g., add a picture, link your ORCiD, pin some of your favorite repositories
    • The point here is to serve as a positive example to working group members as they adopt GitHub best practices
  3. Send your GitHub username to Marty Downs to be added to the LTER Network Office GitHub organization (github.com/lter)
  4. Ask Marty to add you the “network-office” GitHub Team
  5. Complete the LTER GitHub workshop
    • There’s a lot there so don’t try to do it all in one sitting!

We occasionally use the Aurora server (located at aurora.nceas.ucsb.edu) when working with particularly data-intensive projects. Send an email to help[at]nceas.ucsb.edu requesting an account and mention that you are working with the LTER Scientific Computing team. Thomas Hetmank or Nick Outin (NCEAS’ IT personnel) will contact you with directions for setting up an account.

Note that we can onboard working groups to using Aurora as well but only a minority of groups’ projects actually need/want that access.

We use Slack to communicate with one another throughout the day. Register for the NCEAS Slack by clicking here. If you already have a Slack account, be sure to use the email address you used previously to register for this organization.

Find and join our #lter-network-office channel by clicking the magnifying glass button at the top of the “Channels”section. Feel free to join any other channels that you might find interesting! Popular channels include #diversity, #nceas-residents, and #social.

Members of the SciComp team have been part of the authorship team for a couple of great peer-reviewed papers on the philosophical and logistical approaches that we take to support LTER working groups.

Read the following papers:

  • Elmendorf, S.C. et al. Ten Simple Rules for Team Synthesis in Ecological Research. 2026. Methods in Ecology and Evolution.
  • Brun, J. et al. Enabling Data-Driven Collaborative and Reproducible Environmental Synthesis Science. 2025. Methods in Ecology and Evolution

Within the First 3 Months

  • Get Familiar with GitHub Issues
  • Become a Synthesis Fellow
  • Do More Reading

We use GitHub issues extensively to track progress on tasks and make it easier for SciComp team members to (A) collaborate with one another and (B) share progress with working groups in a completely transparent manner. Incidentally this also ensures we act in alignment with our guidance to working groups.

To see our current tasks, check out either our team’s GitHub Project or the issues on this website’s GitHub repository

When you receive a task (or set one for your own improvement as a data scientist), please create an issue for that effort! Fill out the issue metadata and add track its progress with the GitHub project. We’ve created a number of issue templates to make creating them a little easier but as you become more familiar with your role, you should feel free to edit those templates as needed.

Check out past issues to get a sense for how issues tend to be scoped and documented and also how various metadata fields have been leveraged.

This tab panel title is phrased in a sort of tongue-in-cheek way but ultimately, you will want to gain all the same skills that a graduate of our Synthesis Skills for Early Career Researchers (SSECR) course provides early career scientists.

Look through the content on that website and pay special attention to any areas (technical or interpersonal) where you know your skills could stand to be refined. SciComp team members had a strong presence in the design of these materials and the shape of the course closely mirrors patterns that have worked for past working groups.

Check out these older (but still useful!) publications.

  • Hampton, S.E. et al. 2015. The Tao of Open Science for Ecology. 2015. Ecosphere
  • Borer, E.T. et al. Some Simple Guidelines for Effective Data Management. 2009. Bulletin of the Ecological Society of America
  • Fegraus, E.H. et al. Maximizing the Value of Ecological Data with Structured Metadata: An Introduction to Ecological Metadata Language (EML) and Principles for Metadata Creation. 2005. Bulletin of the Ecological Society of America

Going Forward

  • D.R.Y.
  • Plant Seeds
  • Prioritize Your Development!

“DRY: Don’t Repeat Yourself” is one of the mantras of the working data scientist. When a working group asks for you to do something for them, the chances are good that one of your predecessors in the SciComp team has already solved a similar problem!

Glance through the repositories on the LTER GitHub organization in order to become generally familiar with the code we’ve written for (and with) groups in the past. Feel free to copy/paste old code written by the team if it saves you some redundant setup effort.

One of the reasons why groups adore working with our team is that our solutions often solve not just the problem at hand, but several related problems in the future too! Where possible, try to make your solutions as useful as possible to ‘future you’ or future team members. Such effort also helps working groups gain and apply new skills both within their working group and in their careers outside of the working group!

The title of this tabset panel comes from a 1950s American author (though it is often attributed to famous Greek philosophers). To paraphrase:

A society becomes great when people plant the seeds for trees under which they know they will never sit

This is a little grandiose but applies to your work with the SciComp team and, in our opinion, the whole endeavor of reproducible, open science!

Pursuing chances to grow your skillset (whether it be interpersonal or technical), is a benefit both to the SciComp team right now and to your development as a data scientist! As you increase the breadth and depth of your skills, you’ll be better-equipped to help working groups.

Some past SciComp members have opened GitHub issues to track their own skill development! Such issues can be found as sub-issues under the “[SciComp] Improve Working Group Support” issue (#30). Check them out for inspiration if desired.
